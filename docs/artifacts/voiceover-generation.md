# Artifact: voiceover_generation.json

Generated by `byom-video creative-generate-voiceover`.

Schema version: `voiceover_generation.v1`

---

## Location

```
.byom-video/creative_plans/<plan_id>/outputs/voiceover_generation.json
.byom-video/creative_plans/<plan_id>/outputs/voiceover.mp3   (or .wav / .aac / .m4a)
```

The audio file extension is inferred from the `Content-Type` returned by the provider. The JSON artifact is always written first, even on failure, so the generation state is inspectable regardless of outcome.

## Status Values

| Status | Meaning |
|--------|---------|
| `dry_run` | No provider call was made; artifact records what would have been sent |
| `completed` | Audio generated and written to disk |
| `failed` | Provider call failed; `error` field contains the reason |

## Backend Configuration

Add a `voice_generation` backend to `byom-video.yaml` and route `creative.voiceover` to it:

```yaml
tools:
  enabled: true
  backends:
    voice_backend:
      kind: voice_generation
      provider: elevenlabs-compatible
      model: eleven_multilingual_v2
      endpoint: https://api.elevenlabs.io/v1
      auth:
        type: header_env
        header: xi-api-key
        env: ELEVENLABS_API_KEY
      options:
        voice_id: <your-voice-id>
        output_format: mp3_44100_128   # optional
        stability: 0.5                 # optional (0.0–1.0)
        similarity_boost: 0.75         # optional (0.0–1.0)
  routes:
    creative.voiceover: voice_backend
```

### Supported Providers

| Provider | Live calls | Dry-run |
|----------|-----------|---------|
| `elevenlabs-compatible` | Yes | Yes |
| `custom-http-voice` | No (fails with clear error) | Yes |

### Auth Types

| Type | Behaviour |
|------|-----------|
| `header_env` | Reads env var named by `env` at execution time; sets request header named by `header` |
| `bearer_env` | Reads env var; sets `Authorization: Bearer <value>` |
| `none` | No auth header added |

The env var value is never logged, never stored in the artifact, and never written to stdout.

### Backend Resolution

1. If `--backend <name>` is passed, that backend is used directly (must have `kind: voice_generation`).
2. Otherwise the backend name is looked up from `tools.routes.creative.voiceover` (or the route specified by `--route`).
3. If the resolved backend has a different kind, generation fails with a clear error.

## Text Source Priority

`creative-generate-voiceover` resolves voiceover text in this order:

1. `--text "<string>"` — direct text override (source type: `direct_text`)
2. `outputs/voiceover_text.json` — uses the `text` field
3. `outputs/voiceover_text.txt` — plain text fallback
4. Error — no goal fallback; run `creative-voiceover-text` first or pass `--prepare-text`

## Workflow

```bash
# 1. Extract voiceover text from the script (or run automatically with --prepare-text)
byom-video creative-voiceover-text <plan_id>

# 2. Preview what would be sent (no API call)
byom-video creative-generate-voiceover <plan_id> --dry-run

# 3. Verify the env var is set
byom-video creative-generate-voiceover <plan_id> --dry-run --check-env

# 4. Generate audio
byom-video creative-generate-voiceover <plan_id>

# 5. Review the generation artifact
byom-video review-generated-voiceover <plan_id>

# 6. Check overall voiceover readiness
byom-video voiceover-status <plan_id>

# 7. Assemble with voiceover
byom-video creative-assemble <plan_id> --mix-voiceover

# Or run the full pipeline in one make command:
byom-video make <input> --goal "..." --yes \
  --prepare-voiceover \
  --generate-voiceover \
  --mix-voiceover
```

## Flags

### `creative-generate-voiceover`

| Flag | Default | Description |
|------|---------|-------------|
| `--dry-run` | false | Preview request without calling provider; writes artifact with `status=dry_run` |
| `--check-env` | false | In dry-run mode, verify the auth env var is present |

## Security

- The API key is read from the environment variable at execution time only.
- The key value never appears in stdout, in `voiceover_generation.json`, or in any event log entry.
- Only the env var _name_ (`auth.env`) is recorded in the artifact, never the value.
- Dry-run mode does not read the env var unless `--check-env` is passed.

---

## Known Limitations

- Only `elevenlabs-compatible` provider supports live calls in v1. Other provider strings require `--dry-run`.

## CLI Flags for Voice Settings

`creative-generate-voiceover` exposes per-call overrides for voice settings:

| Flag | Description |
|---|---|
| `--stability <0.0-1.0>` | Override `stability` (default: backend config or 0.5) |
| `--similarity-boost <0.0-1.0>` | Override `similarity_boost` (default: backend config or 0.75) |
| `--output-format <format>` | Hint output format, e.g. `mp3_44100_128` (default: backend config or provider default) |

When passed, these values take precedence over backend config defaults and are recorded in `request.stability` / `request.similarity_boost` / `request.output_format` in the artifact.

Values are validated at flag-parse time: `--stability` and `--similarity-boost` must be in `[0.0, 1.0]`.

`make --generate-voiceover` exposes the same options with a `--voiceover-` prefix:
- `--voiceover-stability <0.0-1.0>`
- `--voiceover-similarity-boost <0.0-1.0>`
- `--voiceover-output-format <format>`
